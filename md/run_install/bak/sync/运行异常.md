复现成功，根因确认。 日志铁证：

机制清楚了：

启动时预加载 _load_model → import sentence_transformers 抛 ImportError（被 catch，打 "not available"）→ _model=None。
首请求 detect() 又调 _load_model() → 第二次 import 在 frozen 环境里触发原生崩溃（segfault）→ 绕过 Python 异常处理 → 
进程直接死 = 你看到的"闪退"。run_ccrg.py 的 except 只兜 Python 异常，兜不住 native crash，所以无 traceback。

# 加载失败处理
src/ccrg/splitter/semantic_local.py：

__init__ 加 self._load_failed = False（L33）
detect() 顶部加守卫：if self._load_failed: return self._keyword_fallback(body)（L53-54）
_load_model() 顶部加守卫：if self._load_failed: return self._model（L191-192）
原来会 raise 的失败分支改成置 _load_failed=True + return None

"标记"标记在哪、有何影响
self._load_failed，挂在 SemanticSplitterLocal 实例上（不是全局、不写文件、不进环境变量）。作用域 = 单次进程内该实例。它只做一件事：模型曾经加载失败时，别再重试那个加载。

# 打包方案优化
闪退根因不是 PyInstaller 的问题，也不是 spec 写得烂，而是两个 bug 叠加：
build_copy_ml_lib.py 有 bug：它只复制目录型包，漏掉了所有单文件模块（.py 文件）。typing_extensions.py、threadpoolctl.py 这些 sentence_transformers 的必需依赖根本没被拷进 ml_lib/，导致 frozen 环境里 import 失败。
部署目录跑的是旧版 exe：你日志里的 exe 是 250MB 的全冻结旧包，里面 _internal 塞满了 torch/sentence_transformers，和当前 spec 的 excludes 设计完全对不上。旧版代码没有 _load_failed 防崩溃守卫，第二次 import 触发原生 segfault 就直接死了。
修复方案（两步）：
修 build_copy_ml_lib.py，让它也复制单文件 .py 模块
用新代码重新打包，替换掉部署目录里的旧 exe
