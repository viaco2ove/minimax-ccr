# 2026-10-13 工作日志

## CCRG: WorkflowLLMStrategy 分流器 400 根因 + 修复
- 现象：日志大量 `WorkflowLLMStrategy` 调 `MiniMax-M3` 返回 `400 Bad Request`，但主路径 `minimax_M3_none` 调用正常（`req_f25afe5e_minimax_M3_none.json` 存在）。
- 根因：`splitter/workflow/llm.py` 的 `WorkflowLLMStrategy` 是分流器，把 `extract_user_text(body)` 全量拼出的用户输入（含 `<cb_summary>` 压缩摘要，单请求 250KB+）塞进 system 提示词，且 `_call_via_registry`/`_call_direct` 直发裸 httpx、**未走 `transform_request`**。MiniMax anthropic 接口 system 上限 8000 字符 → 400 invalid params。主路径成功是因为走了 transform_request 把顶层 system 截到 7000。
- 另：`logs/req` 看不到这些 400，因为 dump 代码（`req_*.json` / `*_400.json`）只在 `main.py` 主路径（CURL]4/5/6），分流器无 dump → `grep _400` 数量为 0。
- 修复：`llm.py:_build_messages` 对 user_content 截断到 4000（取尾部最近上下文）+ 最终 prompt 二次截到 7000，与 MiniMaxAdapter.MAX_SYSTEM_LENGTH 对齐。
- 注意：仅影响分流器内部关键词判定调用，不改动主生成路径；如需在分流器侧也落 `logs/req` 便于排查，需另加 dump 代码（本次未做）。
