# 2026-10-12 工作日志

## CCRG: reasoning_effort 支持 MiniMax M3.1
- 需求：让 provider 配置里的 `reasoning_effort` 对 MiniMax M3.1 生效。
- 根因：Anthropic 兼容接口控制推理强度用的是 `output_config.effort`（不是 `reasoning_effort`）；而 `anthropic_adapter.py` 对 `codeplan_anthropic` 协议会直接 `del output_config`，导致 effort 永远发不出去。
- 改动 3 处：
  - `src/ccrg/types.py`：`ProviderConfig` 新增 `reasoning_effort` 字段并从配置读取（顶层优先，兼容之前写的 `capabilities.reasoning_effort`）。
  - `src/ccrg/main.py`：`_provider_config_to_dict` 输出该字段（覆盖流式/非流式所有调用路径）。
  - `src/ccrg/protocol/minimax_adapter.py`：`MiniMaxAdapter.transform_request` 在 `super()` 之后重新注入 `output_config.effort`；策略为「客户端已带合法 effort 则尊重客户端，否则用 provider 配置兜底」，非法值忽略并告警。
- 验证：py_compile 通过 + 模拟 transform_request 三场景（无/客户端有/非法）均正确。M3.1 默认 effort=max，配 medium 会生效。
- 注意：仍需在 `.gateway.json` 的 routing 里引用 `minimax_M3_1:MiniMax-M3.1-Flash-Preview` 才会真路由；若用打包 exe 需重新打包。
