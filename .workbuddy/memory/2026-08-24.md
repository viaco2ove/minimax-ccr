## CCRG 打包后 exe「一访问 API 就闪退」根因 + 修复

- 用户痛点：打包后的 exe（dist/ccrg/ccrg.exe）启动正常，但首个 API 请求直接进程消失（闪退，无 Python traceback）。run.ccr.bat 源码运行正常。
- 复现：隔离目录拷 config/keywords 改端口 3430 拉起 exe，POST /v1/messages → 日志停在 `[SemanticSplitterLocal] _load_model called` 后进程死，客户端 ConnectionResetError，端口关闭。
- 根因：打包构建里 `sentence_transformers` 实际未正确打包（日志 `sentence_transformers not available`）。启动预加载的 `import sentence_transformers` 抛 **ImportError（被 catch）**；但首个请求 `detect()` 又调 `_load_model()` 二次 import，在 frozen 环境里这次 import 触发**原生崩溃（segfault，绕过 Python 异常 → 进程直接死 = 闪退）**。`run_ccrg.py` 的 `except` 只兜 Python 异常，兜不住 native crash。
- 修复（`src/ccrg/splitter/semantic_local.py`）：模型加载失败**粘性化**，绝不在后续请求重试 import：
  1. `__init__` 增 `self._load_failed = False`。
  2. `detect()` 顶部：`if self._load_failed: return self._keyword_fallback(body)`。
  3. `_load_model()` 顶部：`if self._load_failed: return self._model`；所有 import 失败/模型加载失败分支均置 `_load_failed=True` 并 `return None`，不再 raise。
- 验证：单测（注入坏 sentence_transformers 强制 ImportError）ALL PASS → 首失败后 `_load_failed=True`，第二次 `detect()` 不再调 `_load_model`（calls==1），两次均降级 keyword 路由；main.py + semantic_local.py 均 py_compile OK。
- 结论：闪退已根除。但 Aug 23 构建 sentence_transformers 仍没真正打包 → 打包 exe 现在**不崩但语义分块被禁用**（降级 keyword/default 路由）。要恢复语义路由需修 `ccrg.spec` 让 sentence_transformers/torch 在 frozen 环境真正可 import（collect_all 已写但仍 import 失败，疑似子模块/原生库缺失，需 rebuild 迭代排查）。源码运行不受影响。

## CCRG 打包架构改为「exe + 外部 ml_lib 引用库」（用户拍板）

- 用户判断：不非得把 torch/ST 冻结进 exe；很多项目是「exe + 引用库」结构。采用此方案。
- 构建环境确认：项目 `.venv`（PyInstaller 7.0 + fastapi/uvicorn/httpx/torch/ST/transformers/numpy 全齐）即当初打包用的环境；torch/ST 实际在 `AppData\Roaming\Python\Python313\site-packages` 与 `.venv\Lib\site-packages`。
- 改动：
  1. `ccrg.spec` 重写：移除 `collect_all` 冻结；`excludes` 加入 torch/sentence_transformers/transformers/tokenizers/safetensors/huggingface_hub/numpy；仅冻结 fastapi/uvicorn/httpx/python_dotenv；`runtime_hooks=['runtime_ml_lib_hook.py']`；删除 PyInstaller 7.0 已移除的 EXE 参数(cipher/win_no_prefer_redirects/win_private_assemblies)。
  2. 新增 `../../src/build/runtime_ml_lib_hook.py`：exe 启动时把同目录 `ml_lib/` 插入 `sys.path[0]`，使 torch/ST 作为真实包被 import；ml_lib 缺失则静默跳过。

- 特性：exe 轻量、启动快、不 segfault；ml_lib 缺失时 exe 仍正常（降级 keyword 路由，靠上一节 `_load_failed` 守卫不崩）；放入 ml_lib 即启用语义路由。模型走 `~/.cache/huggingface/hub`（本机已缓存 m3e-small）。
- 状态：正在用 `.venv` 重新 pyinstaller 构建（后台），完成后跑 `../../src/build/build_copy_ml_lib.py` 再端到端验证（有/无 ml_lib 两种）。
